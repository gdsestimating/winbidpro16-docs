# Upgrading from v15 to v16

This page answers the most common questions about transitioning from WinBidPro v15 to v16.

---

## How Data Works in v16

v16 is cloud-based. All vendor catalogs, framing systems, pricing, and jobs are stored securely on GDS servers (Amazon AWS). This means:

- **Shared data** — all active users on your account see the same catalogs, framing systems, and jobs
- **Real-time updates** — if one user updates pricing or a framing system, everyone sees the change immediately
- **Log in anywhere** — users can sign in from any installed machine
- **No server required** — no internal file server or shared network drive is needed

---

## Can I Run v15 and v16 at the Same Time?

**Yes** — you can run both versions simultaneously.

v16 installs as a completely separate program and does not interfere with v15. With your current subscription you can:

- Continue using v15 for existing jobs
- Begin creating new jobs in v16
- Transition gradually at your own pace

:::info

v15 will remain on your machine and fully functional, but it is no longer receiving updates.

:::

---

## Will My v15 Jobs Still Be There?

**Yes.** v15 does not go away. You can continue opening and working on existing v15 jobs at any time.

New jobs must be created in v16. v15 jobs cannot be migrated into v16.

---

## Can I Migrate My v15 Vendor Catalogs or Framing Systems?

v16 uses a new cloud-based database structure, so v15 data does not automatically transfer. However, GDS has an internal migration tool that can transfer eligible vendor catalogs and framing systems into v16.

| Eligible for Migration | Not Eligible |
|---|---|
| Vendor catalogs (parts & pricing) | Jobs |
| Framing systems | |

Some cleanup or adjustments may be required after migration. Many customers use this as an opportunity to standardize naming conventions and clean up legacy data.

:::tip

Ready to begin? Follow the step-by-step instructions in the [Catalog Migration Guide](/docs/v16/basics/upgrading/v15-catalog-migration).

:::

## Recommended Transition Approach

Most customers follow this process:

1. **Install v16** alongside v15
2. **Start building new jobs** in v16
3. **Keep v15** for historical reference and any active projects
4. **Gradually phase out v15** once the team is comfortable

This approach avoids disruption to active projects and gives everyone time to get familiar with v16 at their own pace.
